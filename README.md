# 航民股份四车间 · 试样管理

参考提供的 9 张截图制作的纯前端应用，使用 React 19、TypeScript、Ant Design 5 和 Vite。

## 启动

```sh
npm install
npm run dev
```

访问 http://localhost:5173 。

## 构建

```sh
npm run build
npm run preview
```

构建文件位于 `dist/`，可以放入任何静态网站服务器，支持相对资源路径。

## 页面与交互

- 工作台：待办入口、班组切换、人员任务卡片。
- 打样：任务分类、配方录入、染助剂增删、比例编辑、配方带入、本地保存。
- 抄样：条件查询、历史配方详情抽屉、配方编辑。
- 对样：扫描或输入流程卡后展示染色对样详情，包含流程卡资料、按阶段合并的配方表、底部操作栏及全屏显示。演示编号为 `Y2606302501`；连缸号、复样申请、加料和对样结果保存在 `lab-matching-details` 本地存储中。
- 配方审核：条件筛选、配方详情、打样过程、基础信息、审核、浏览器打印。
- 配方变更：展示被退回的配方。
- 打样进度：任务筛选、多选、详情。
- 配方查询：记录选择、配方与流程卡联动、编辑与打印。

使用内置演示数据，配方编辑、审核状态和打样配方保存至 localStorage；未连接后端。滴液、交接班等业务动作为演示反馈。截图未展示的外围模块提供空状态页面。

## 染色工艺审核

入口：顶部“生产管理” → 左侧“工艺审核 / 染色工艺审核”。

包含流程卡资料、减量/中和/染色工艺切换、阶段新增与删除、工艺模板选择、温度/速率/时间/说明编辑、总时长自动汇总、历史工艺查询及引用、染色配方表和审核确认。工艺数据与审核状态使用 `lab-dye-process` 本地存储。编辑已审核工艺会将其恢复为待审状态。初始染色工艺 7 个步骤，总时长 92 分钟。

## 化验室工长工作台

参考工长看板重新组织为班组打样进度、带布进度、待办事项、常用入口四个区域。

- 班组进度表展示全部、甲、乙、丙班的已分配、进行中、已完成和超时数量；打样进度标题旁的班组筛选同步影响统计和待办。
- 已分配包含进行中和待确认；超时与状态交叉统计，不能相加。已完成为当前数据集的数量，不表示当日完成量。
- 带布按大货、预打样、回修、复样汇总待带布、带布中和已完成数量。
- 待办包括大货订单审核、预打样订单审核、待分配大货、待分配回修、待分配预打样、配方确认；三类待分配按当前班组、任务类型与待分配状态分别统计。
- 十个常用入口支持编号直达和显示设置，显示偏好存入 `lab-workbench-shortcuts`；取消设置不改变原偏好。
- 配方记录、对样查询、工艺查询、染缸计划连接现有页面；其他查询、报表沿用占位页面。待办跳转保留现有处理：配方确认进入配方审核，任务统计进入打样进度，其他待办提示入口预留；目标页尚未应用工作台筛选条件。
- 统计沿用 `lab-workbench-v1` 本地演示数据，与其他业务页面演示数据独立。页面支持刷新和窄屏重排，小窗口可滚动查看。

## 不良配方

入口：试样管理 → 配方 → 不良配方。

- 对样累计保存至少 3 批加料后自动进入列表，按流程卡去重；已有历史记录同样适用。
- 工段长填写姓名、判断依据，选择重新打样或直接调整配方比例。
- 重新打样任务显示在“打样”页面顶部，录入新比例并保存后回写对应流程卡，状态变为待对样。
- 直接调整保存该流程卡的新比例并恢复待对样；保留调整前后配方、处理原因、姓名及时间。
- 处理后再次加料会重新进入待工段长处理；尚未完成的重新打样任务不重复生成。
- 数据保存在 `lab-matching-details`。当前为本地前端流程，姓名手工录入，未接入后端身份或角色权限。

不良配方列表采用订字/色号、流程卡、日期和状态筛选，展示加料比例及复样进度。点击“去处理”打开流程卡和配方详情弹窗，底部可选择无需变更、创建复样、变更编辑；支持勾选待处理记录批量标记无需变更。无需变更保留原对样结果，后续新增加料后仍会重新进入待处理状态。回修页签当前无数据。演示流程卡的基础信息仅供页面演示。

“变更编辑”支持增删染助剂及编辑浴比、阶段、染助剂代码、比例、算法、单位、工艺和 pH。算法与单位联动，取消会恢复原配方。保存范围可选当前流程卡，或本地已存在的同订字同色号关联流程卡；缺少订单关联信息时禁用后一入口。变更记录保留完整配方快照、浴比与范围，对样页同步读取保存的配方字段。当前未接入后端订单主配方服务。

## 染色工艺审核中的配方变更

“配方-染色”区域的“编辑”可修改浴比和染助剂明细。配方实际发生变化后，底部“审核”变为“提交变更”，填写原因后进入“配方变更”页顶部的工段长审核列表。工段长可对照变更前后配方，通过或退回；通过才更新生效配方，退回保留原配方且允许重新编辑提交。取消编辑恢复原值，待审核时阻止重复提交。数据与审核记录保存在 `lab-dye-formula-changes`，工段长姓名手工录入，沿用本地前端模式。

## 打样页面布局

打样页面采用左侧任务卡片、顶部布料资料、左侧两枪配方对比和右侧配方编辑布局。大货、回修、复样及预打样支持分类切换；复样页签保留不良配方重新打样任务。配方支持增删、上下移动、阶段与比例编辑、带入（F8）、清空及按任务独立保存（`lab-sampling-drafts`）；原 `lab-sample` 数据在国张711任务中读取。滴液记录保存在 `lab-sampling-drops` 并提供查询。现有配方提审与交接班仍为本地反馈。

## 进仓确认

入口：试样管理 → 配方 → 不良配方下方的“进仓确认”。对样结果为“通过”或“通过并直送”的流程卡自动进入列表。支持流程卡、订字、色号及确认状态筛选。进仓前可调整浴比、阶段、染助剂、比例和算法；算法联动单位，调整原因和操作人必填，保存回写对应对样配方。调整后保持待确认，确认时保存快照与操作记录，已确认详情只读。源配方、浴比、加料或对样结果变化后原确认失效。数据沿用本地对样记录，确认历史保存在 `lab-warehouse-confirmations`；不执行实际仓储库存入账，未接入后端身份权限。

## 流程卡配方编号

编号格式为 `C + 浴比 + 日期（YYYYMMDD）+ 流水号码（至少4位）+ v版本号`，例如 `C8202609170001v0`。进仓确认列表支持显示和搜索配方号，对样、不良配方、进仓确认及染色配方详情同步展示。未记录版本的对样配方从 v0 开始；浴比、染助剂、比例、算法、工艺等配方内容实际保存变更后递增，确认、取消和单独记录加料不递增。染色配方在审核通过且生效内容变化时递增，使用原配方或退回不递增。无流程卡关联的旧打样/抄样静态演示编号保留。进仓操作记录保存调整前后编号。

配方首次生成新编号时登记日期与每日流水（0001 起），同一流程卡后续变更保留该日期和流水，仅更新浴比与版本。编号登记保存在 `lab-formula-number-registry-v2`，刷新后不重新分配。历史操作记录中的旧编号保留作为当时快照。

### 开卡审核

配方审核下方新增开卡审核，共用染缸排产数据；排除生产中和已转卡计划。左侧搜索并选择计划，右上显示计划详情，右下按已生效版本查看配方。待确认变更不生成新版本；历史版本可直接选用开卡。待开卡计划无需提交或等待配方变更确认；审核通过使用所选版本，保存配方快照、操作人和时间，并回写排产已转卡标记。当前使用浏览器本地演示数据。
