# 工作台打样与对样信息合并设计

## 意图

取消工作台顶部“打样 / 对样”页签，将“对样进度”和“半检超时”并入打样工作台，使班组在同一页面同时查看打样、对样及对应的超时风险，减少切换操作。

## 目标

- 保留现有“变更”和“待办事项”首行，不改变其操作入口。
- 同屏显示打样进度、回修超时、对样进度和半检超时。
- 让每类进度与对应异常相邻，方便从总体状态进入异常处理。
- 桌面端保持高信息密度，窄屏不出现横向滚动。
- 继续使用现有班组筛选、刷新和任务跳转逻辑。

## 非目标

- 不调整统计数据的计算口径。
- 不新增后端接口、任务状态或业务字段。
- 不改变底部化验室回修、染色加料及颜色判断统计的内容。

## 采用方案

采用“进度与异常成对展示”的方案：

1. 第一行保留“变更”和“待办事项”。
2. 第二行左侧为“打样进度”，右侧为“回修超时”。
3. 第三行左侧为“对样进度”，右侧为“半检超时”。
4. 底部继续展示四张统计卡片。

桌面端业务行使用约 `60% / 40%` 的两列比例，让进度表获得更充足的列宽。两张进度卡片以及两张超时卡片分别保持一致的标题高度、边距、表头和空状态。

## 响应式规则

- 大于 `850px`：每个业务行按“进度 / 超时”两列展示。
- 小于等于 `850px`：改为单列，顺序为“打样进度 → 回修超时 → 对样进度 → 半检超时”。
- 所有卡片宽度使用可收缩网格，不设置导致页面横向滚动的固定最小宽度。
- 表格保持紧凑密度；必要时缩小单元格内边距，不通过横向滚动解决布局问题。

## 组件与交互

- 移除顶部“打样 / 对样”Tabs。
- “打样进度”继续保留班组选择、当班天数、查看任务和刷新操作。
- “对样进度”复用同一个班组状态，不再设置独立班组筛选，避免同一页面出现两个不同班组口径。
- 页面级刷新同时更新打样、对样及超时数据；对样卡片可保留一个具备无障碍名称的刷新图标按钮，或统一由打样卡片刷新入口控制。
- 超时数量和超时时长使用错误色；完成数量使用成功色；不可用数据继续显示“—”。
- 行和数字入口保持可点击语义，键盘焦点状态遵循现有 Ant Design 风格。

## 备选方案

- 同类横向比较：打样进度与对样进度并排、两个超时模块并排。比较方便，但中等宽度下进度表过窄。
- 两个带切换的大模块：进度和超时各使用页签切换。页面紧凑，但会隐藏关键异常信息。

最终选择成对展示方案，因为它最符合工作台“同时看状态、立即找异常”的使用目的。

## 验收要点

- 页面不再出现“打样 / 对样”页签。
- 四个业务模块无需切换即可查看。
- 当前班组切换后，打样和对样数据保持同一口径。
- 约 `820px` 宽度下模块单列排列，页面没有横向滚动。
- 原有任务跳转、刷新、空状态和统计卡片仍能正常使用。
