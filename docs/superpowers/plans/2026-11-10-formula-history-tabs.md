# 配方履历分页签实施计划

**Goal:** 在同一个履历详情弹窗中完成配方、使用记录和变更对比查看。
**Architecture:** 保留 main.tsx 的查询与本地保存逻辑，抽取独立 FormulaHistoryDialog 负责三页签布局，独立纯函数负责版本及关联流程卡筛选。
**Tech Stack:** React 19 / TypeScript / Ant Design 5。
**Spec:** docs/superpowers/specs/2026-11-10-formula-history-tabs-design.md

## 约束与检查重点
保留编辑、打印和核算；不生成新审批记录。小样无流程卡、初始版本、浴比更换、编辑中切换及关闭均需要处理。

## 实施步骤
- [x] 为唯一版本、默认可用版本和所选版本关联流程卡添加行为测试。
- [x] 实现 src/formula-history-view.ts 并运行测试。
- [x] 新增 src/FormulaHistoryDialog.tsx 与样式，包含摘要、统一选择、三个页签、原位流程卡资料与版本对比。
- [x] main.tsx 接入组件，移除旧履历分栏与叠加版本弹窗；保留本地保存及核算弹窗。
- [x] 验证编辑保护、小样空状态、初始版对比、构建及全量测试，尽可能查看实际布局。

## 验证结果
- 新增 2 项版本筛选测试：先失败，实施后通过；完整测试集 63 项通过。
- 实际 Chrome 画面检查：1838×880、1000×800；弹窗主体无水平溢出，宽表格单独滚动。
- 交互验证：三页签、默认可用版本、浴比切换重置版本、小样无生产卡、初版无前版、编辑中切换阻止、关闭继续编辑、取消及保存。
- 打印媒体验证：打开时隔离背景并保留订单标题；关闭后其他页面恢复打印。
- 独立复查发现并修复：差异高亮、未支持名称编辑、遗漏流程卡资料、打印订单标题与关闭后打印隔离。
- 决定：保留当前检出目录，直接修改用户正在预览的应用；本次未提交或推送。
